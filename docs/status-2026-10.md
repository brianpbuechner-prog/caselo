# Caselo status, October 2026

Audit of `main` at commit `7a72600` (merge of PR #11, 2026-10-21). Every
file in the repository was read. No app code was changed. Tests, type check,
and lint were run locally (see "Test coverage").

The planned language for the student support model is:
"Slipping", "Worth a check-in", "Finding footing", "Growing".

## The hard rule

Student data never leaves the browser. Measured against that rule:

- No code path sends a name, ID, or one student's values over the network.
- The AI draft is the only request that carries anything derived from a
  file. It is designed to carry aggregates only, but two fields (`label` and
  `grade`) accept any short text, so the rule can be broken by a typed label
  or a mis-mapped column (finding 1). The server check does not stop it.
- Browser spell check on the search and label inputs can send typed names
  to an online service (finding 4).
- Downloads and prints (CSV, the names PDF, the mapping file) leave the tab
  only when the person asks, and go to their own device. The print dialog
  can offer cloud destinations; that choice belongs to the browser.

The ranking below puts these first.

## What is built

Caselo is a single-page Vite, React 19, and TypeScript app with one server
function. It is deployed on Vercel at caselo.org. Git history shows 11 merged
pull requests between 2026-10-11 and 2026-10-21:

- Phase 1: upload, column mapping, grouping, the rules engine, results, and
  tests.
- Input: Excel and OpenDocument, paste, header row detection, more Infinite
  Campus aliases, automatic column reading that skips the review page when
  Caselo is sure.
- Phase 2: the de-identified summary with small-cell suppression, printed as
  the default PDF.
- Phase 3: the optional AI draft (preview, Send, insight cards by role, ASCA
  goals, number check, PDF option) through `api/draft.ts`.
- Language: tiers and flags renamed on screen, "Slipping, no signals yet",
  the results headline leading with who needs support, and Growing renamed to
  Gaining ground.

Planned and not built (from the README): a bring-your-own-key option for the
AI draft, community context from the Census ACS API (Phase 4), and more
export types, SIS platforms, and roles.

## What each part does

| Part | Files | What it does |
|---|---|---|
| App shell | `src/App.tsx`, `src/main.tsx` | Four stages: landing, file review, results, and "How Caselo read your files". Holds files, analysis, and the AI draft in React state only. "Clear data" empties state and stops the DuckDB worker. |
| File reading | `src/lib/files/` | Decodes text, rejects binary, detects the delimiter (comma, tab, pipe, caret) and the header row, converts spreadsheets to CSV with SheetJS (loaded only when needed), and guesses a snapshot label (Q1, S2, T1, Fall) from the file name. |
| Field catalog | `src/lib/sis/` | The Infinite Campus field list: default headers, aliases, categories, required fields per category, and student ID fields in order of preference. One catalog is registered. |
| Column mapping | `src/lib/mapping/` | Matches headers by exact name, fuzzy name, and the values in the first 200 rows. Marks uncertain matches. Saves and loads a mapping as JSON (header names only). |
| Grouping | `src/lib/grouping/` | Decides how files become snapshots (`plan.ts`), detects one row per student or many, rolls many-row files up to one row per student in DuckDB (`rollup.ts`), and merges same-label files by student ID (`snapshots.ts`). |
| Database | `src/lib/db/` | DuckDB-WASM in a Web Worker with an in-memory database, served from the site, with extension download and autoload turned off. Tests use a Node DuckDB runner behind the same interface. |
| Rules | `src/config/rules.ts`, `src/lib/rules/engine.ts` | Three rules (attendance at 10% absent, academics at GPA below 2.0 or a failing course grade, behavior at 3 incidents), at most one signal per area, support level from the signal count. Every threshold is adjustable and every signal carries a plain reason. |
| Comparison | `src/lib/compare/` | Evaluates every snapshot, counts change between the last two (only for rules present in both), assigns direction per student (`movement.ts`), finds students close to a line, and builds patterns: grade rates, overlap, distributions, "start here", and grade hotspots. |
| Language | `src/lib/language.ts` | On-screen names for support levels and directions. Code keeps `tier` and `flag`. |
| Results page | `src/components/results/` | Headline, support bar, "Since" changes, role-based "Start here" or "Where to look", "Slipping, no signals yet" (or "Close to a line" with one snapshot), Patterns, the full student list with filters and CSV export, the student drawer, and the Rules panel. |
| Roles | `src/lib/roles/roles.ts` | Counselor and Administrator. The role changes only the "start here" and slipping sections; the full named student list is shown to both. |
| De-identified summary | `src/lib/summary/` | Counts and rates only. Counts under 10 show as "<10", with complementary suppression ("*"). Printed as the default PDF and used as the AI draft input. |
| AI draft | `src/lib/ai/`, `api/draft.ts`, `src/components/results/AiDraft.tsx`, `DraftView.tsx` | Previews the exact JSON, posts it to the same-origin function on Send, validates it against a strict schema on the server, calls the Messages API with a fixed public prompt and a JSON output schema, and checks every number in the reply against the payload. The draft is editable, held in memory, and optionally printed. |
| Preferences | `src/lib/preferences.ts` | Saves role, thresholds, and table density to localStorage, sanitized on load. |
| Export | `src/lib/export/csv.ts` | Student list to CSV in the browser, with support level, tier number, names, IDs, values, reasons, and direction. |
| Security headers | `vercel.json`, `vite.config.ts` | CSP with `connect-src 'self'`, no referrer, nosniff, and a permissions policy. The CSP is also injected as a meta tag in builds (not in dev). |
| Sample data | `scripts/generate-sample-data.mjs`, `public/sample-data/` | About 300 invented students across Q1, Q2, a behavior file, a renamed-header TSV, and an xlsx workbook. |

## Where row-level student data could leave the browser

Row-level data means names, IDs, or one student's values. Summary: no code
path sends row-level data over the network. The only network request that
carries anything derived from a file is the AI draft, which sends aggregates
plus two free-text fields that are not limited to aggregates (finding 1). Everything else that leaves the tab is a file or
print the person starts.

| # | Path | What leaves | To where | Controls | Risk |
|---|---|---|---|---|---|
| 1 | AI draft, "Send" | Aggregated counts and rates, the snapshot `label`, and each `grade` value | caselo.org `/api/draft`, then Anthropic's API | Preview of the exact text, explicit Send, server schema check (counts 10 or more, fixed rule text), 64 KB cap, logs status codes only | High. `label` and `grade` accept any short text with letters, so a typed name or a mis-mapped grade column would be sent (finding 1). |
| 2 | "Export CSV" | Names, IDs, grade, values, reasons, direction for every row in the filtered list | Local Downloads folder | Button press | Expected. Untested. |
| 3 | "Download PDF" with "Include student names" ticked | The full results page and student list | Browser print dialog, which may offer cloud destinations | Opt-in per print, reset on `afterprint`; default print and browser Print show the no-names summary | Expected. The default depends on CSS only and is untested. |
| 4 | "Download PDF" default | De-identified summary, including grade labels | Browser print dialog | Suppression under 10 | Low. Grade labels come from the data (same as row 1). |
| 5 | "Download mapping" | Header names | Local Downloads folder | Headers only | Low. If header detection picked a data line, those values would be saved as "headers". |
| 6 | "Copy data" and "Copy all as text" | The AI payload and the draft | Clipboard | Button press | Low. Same content as row 1. |
| 7 | Browser spell check | Text typed in the student search box and label inputs | The browser's spelling service, if enhanced spell check is on | Paste box and draft editor set `spellCheck={false}`; search and label inputs do not | Medium (finding 4). |
| 8 | localStorage | Role, thresholds, density | This browser | `sanitize` keeps only known keys | None for student data. |
| 9 | Network fetches | Sample files only, same origin | caselo.org | CSP `connect-src 'self'`; DuckDB extension autoload off; WASM and fonts served locally | None. The dev server runs without the CSP. |

Outside the code: browser extensions can read any page, and Vercel keeps
its own request metadata for the function. The README states Anthropic's
retention terms; those are a policy claim to keep current, not something the
code enforces.
